🔗 单入口设计（Electron 桌面应用为唯一活跃入口）

🖼️ Electron 桌面应用（唯一活跃入口）
React + TypeScript + Vite 渲染器，FastAPI 后端作为子进程运行。支持文件对话框获取绝对路径。三 TAB 架构：Discovery / Q&A / Exec。通过 WebSocket 实现流式 Q&A 和实时执行日志。路由：/（MainPage）、/generator、/pipeline。执行 cwd 为项目根目录，脚本临时写入 ./cache/。
⌨️ CLI 命令行 REPL 【已废弃，代码保留】
命令行交互式 REPL，代码保留但不再维护（constitution.md §6.1、spec.md v1.7.0）。不再支持 --dry-run 和 Y/N 确认流程。

🔀 三 TAB 关键交互流

1
DiscoveryTab 意图匹配
用户输入自然语言 → POST /session/{id}/intent → 两阶段匹配（关键词粗筛 + LLM 精排，不传 history，DC-0106）→ ≥0.85 直接 PARAM_COLLECT / ≥0.50 展示 top-1 + 备选 / <0.50 展示 top-3 关键词候选
2
QATab 知识问答（WebSocket 流式）
用户提问 → WS /ws/chat/{id} → handler 读取 session.qa_history 作为对话上下文 → 代码层分支：locked_template 存在时走模板知识问答，不存在时走 GIS 专家问答 → 流式返回 chunk → 完成写回 qa_history（DC-UX-14）。前端独立维护 qaMessages（DC-UX-15）
3
ExecTab 脚本执行与自动诊断
用户确认 → WS /ws/execute 实时日志 → 成功返回 IDLE / 失败进入 ERROR_RECOVERY → 自动触发 LLM 诊断（无需按钮）→ 诊断结果 inline 展示在 ExecTab（根因 + 建议 + can_auto_fix + 【修复命令参考】代码块，ReactMarkdown 渲染）→ 修改参数 / 放弃任务
4
Pipeline 多步执行
用户进入 /#/pipeline → 添加多个步骤模板 + 自动关联参数 → POST /pipeline 预览合并脚本 → 复用 /ws/execute WebSocket 执行多步合并脚本 → 流式日志推送
5
GeneratorPage 模板生成器
用户进入 /#/generator → 文档输入（支持多文件 HTML/Markdown）→ POST /generator/parse-document 清洗 → WS /ws/generator/generate 流式 LLM 生成 → Monaco 代码编辑器预览 → ScriptSecurityChecker 安全校验 → Jinja2 语法校验 → POST /generator/save 保存 → 后端热重载 rescan()

🚫 安全红线 (Security Principles)

P1 — 模板化命令，杜绝幻觉
所有 GDAL 命令必须通过 Jinja2 模板渲染生成，严禁动态字符串拼接。LLM 只负责选择模板 ID 和填充参数。
P2 — 先展后行
任何脚本必须向用户完整展示内容，获得明确确认后才可执行。WebSocket 执行过程实时可见。
P3 — 最小权限
脚本临时写入 ./cache/ 目录（DC-0105），不污染用户数据区。输出路径由用户指定，绝对路径直接放行。时间戳防覆盖由前端控制。路径经 normalize 后使用。
P4 — 模板知识唯一
用法指导类知识仅来源于 J2 模板元数据，基硎概念类回答由 LLM 参数知识提供，禁止调用外部 API。
P5 — 最小依赖
生产依赖锁定 7 个库：anthropic、beautifulsoup4、jinja2、json5、pydantic≥2.0、pydantic-settings≥2.0、tenacity≥8.0。FastAPI / uvicorn 为 dev 依赖。降低供应链攻击面。
